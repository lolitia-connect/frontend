### 1.1 旧标签冲突，实施时必须固定官方提交

本地 `v1.10.0` 指向 `bd39e3e`，官方同名标签指向 `4c564ba`。两个提交的 tree 都是 `5dc52c77e9bb86deff8c3446962fe9c25cf7bbbb`，**文件快照相同，但提交历史不同**。直接对本地标签做 `git log v1.10.0..v1.22.0` 会得到 297 个提交，把旧历史算进待同步范围。

已将官方版本固定到独立引用，保留本地标签：

```powershell
git fetch --no-tags offical-upstream refs/tags/v1.10.0:refs/upstream-tags/offical-upstream/v1.10.0 refs/tags/v1.22.0:refs/upstream-tags/offical-upstream/v1.22.0
git log --no-merges --reverse --oneline refs/upstream-tags/offical-upstream/v1.10.0..refs/upstream-tags/offical-upstream/v1.22.0
git diff --stat refs/upstream-tags/offical-upstream/v1.10.0 refs/upstream-tags/offical-upstream/v1.22.0
```

以上命令在 frontend 仓库执行。后续使用固定 SHA 或上述引用，不强制改写本地旧标签，也不以浮动的上游 main 作为代码或 Swagger 来源。

## 2. 同步原则与保留项

推荐从本地 main 做**逐功能移植**。前端和上游仍是 Vite + React + legacy + 共享 UI 的 monorepo，不能套用 backend 的架构冲突数量；本轮也未尝试 merge，不能声称直接合并必然失败。但服务层大规模重生成、上游功能删除以及 fork 定制并存，逐功能移植更便于验收。

本次在用户当前 main 工作区实施，保留已有修改；未创建新分支或提交。所有条目的本地提交均为“未提交工作区”，不虚构落地 SHA；上游来源沿用下表的固定提交。不以“所有上游提交都成为祖先”作为完成标准。

| 本地功能 | 保留要求与回归场景 |
| --- | --- |
| 多协议实例 | 保留 `protocol_id`、协议 `id`、`name` 的本地映射；同类型多个入站不能按 type 去重、覆盖或串号 |
| 无限流量 | 保留 `traffic_unlimited` 的独立语义，不能恢复成仅按 `traffic == 0` 或 `!traffic` 判断 |
| Stripe 支付 | 保留本地 Checkout Session/checkout_url 流程；官方 Stripe 嵌入式类型不代表本地后端也返回相同对象 |
| 插件 | 后端 native_routes.go 仍注册 `/v1/admin/plugin/*` 与 `/v1/admin/plugins/*`；保留列表、上传、启停、重载及本地服务封装 |
| 兑换码、分组与本地服务 | 保留 redemption/group/auth 等 fork 服务与页面，不能被上游生成器清理丢失 |
| 订单类型展示 | 保留 type 5/兑换码文案与最新修复，区分订单 type 和支付/履约 status |

| 认证与本地化 | 保留注册流程、已有验证设置和多语言 key，合并而非整文件覆盖 |
| 发布与品牌设置 | 保留 fork 发布策略、安装地址及已主动移除的赞助展示，不引入官方发布或赞助内容回退 |

### 4.1 API 源与生成链路（F01）的执行要求

原本地生成器读取 `perfect-panel/ppanel-docs/main`，官方目标版本改用 `perfect-panel/frontend/main`。**这两者都不是本地可复现的契约来源**。本次已改用 backend-contract.go/mjs 导出本地 schema，下列要求作为生成链路的审阅依据：

1. 从 backend `04ea4282` 的 routes、native_routes、v2_order_routes、types、apis 形成端点/字段矩阵。现有 ppanel.json 是候选输入，不能假定包含手写路由的最新变更。
2. 定义并验证 Swagger 生成/补充方式。backend Makefile 未提供已确认的 Swagger 生成 target，因此不能在实施前写成一个“已存在可运行”的导出命令。
3. 引入上游 docs/public/swagger、openapi-templates、配置 hook；以**本地分域文件**作为 schemaPath，记录本地后端 SHA、上游参考 SHA 和生成步骤。
4. 将生成器外的 fork 服务（插件、分组、兑换码等）纳入 schema，或保留在不会被清理的适配目录；核对已有 import 和函数命名。
5. 处理响应 required hook、可空字段、空 data、路径参数、V1/V2 命名变化；不能因为生成器把字段设为 required 就假定后端总是返回。
6. 生成并检查 routes/method/auth/body/result 的真实差异；API 产物与页面迁移分开提交，第二次生成应无差异。

特别检查私有 Edge manifest 不进入普通用户页面公开请求流程；`/v2` 和 `/api/edge` 不会自动由仅匹配 `/v1` 的 Pages function 转发。实际需要浏览器调用的 V2 路径要单列部署路由测试。

### 4.2 访客支付（L01/L02）的最低正确行为

官方 target 的 user typings 含 checkout_token/V2，但 purchasing/order 仍从旧 localStorage 记录展开 authParams，checkout 没有完整令牌传递；生成字段不等于页面已升级。

- 从 purchase 响应取得 token，按订单保存最少必要数据，不再保存或轮询携带密码/完整注册信息。
- 刷新、支付跳转返回、跨标签页按所选存储方案恢复；token 不放进日志、埋点或外链 URL。
- status 以 token 或已登录订单所有者授权；token 缺失/失效停止无效轮询并给出可恢复状态。
- checkout、V2 session 等请求分别按本地 handler 的真实授权要求发送字段，不套用上游通用假设。
- 保留本地用户点击后才发起支付、Checkout Session/checkout_url 逻辑；不引入自动查询导致的重复支付会话。
- 核对完成/关闭/过期状态、订单 type 与 status，结束后清理敏感暂存。
- V2 事件 UI 若本次不启用，明确记录“服务/类型已适配、页面仍使用 V1”；它不阻塞安全的 V1 购买流程，但也不记为 V2 页面已完成。

### 4.3 协议表单（F04/L03/L04）的本地约束

- upstream v1.22.0 有 SSR 和 Snell 表单，没有本地 Nowhere 表单；不能直接覆盖协议列表。
- SSR：cipher/server_key/ssr_protocol/obfs 等以 backend allowlist 为准；不开放 origin/verify_*，UDP-only 与非 plain obfs 的组合应拒绝。
- Nowhere：type 为 nowhere、TLS、version=1、ALPN 默认 `["now/1"]`、network 为 mix/tcp/udp；跟进 backend 真实校验。证书默认值不能让启用状态的表单自动形成非法配置。
- 保留 Shadowsocks 简单 obfs，以及本地运行时真正使用的 Reality、transport、Mieru multiplex 等；官方 plugin 模型不能替换本地字段。
- 保留未知但由 backend 返回的隐藏字段；type+id 决定实例身份，name 不能成为唯一标识。
- pin 是节点报告的只读数据，不提供手填替换输入。节点侧 header 和证书验证仍需独立验收。
- SSR/Nowhere 依当前节点交接说明尚不具备完整运行能力；实施时复核 node-backend 代码，未支持前使用明确能力门槛，不能仅凭保存成功上线。

- **最高风险：契约重生成覆盖 fork**。先完成 schema 与本地服务保护，再迁页面；保存每批生成 diff。
- **最高风险：访客支付授权不兼容**。L01 先于其他视觉改动，frontend 与 backend 04ea4282 配对验证；不能单独回滚到只发 identifier 的旧前端。

- **高风险：静态部署只代理 V1**。在 Pages/反代上验证真实 V2 路径，不能用本地开发代理通过代替上线证据。
- **中风险：新工具链与旧代码**。沿用本地依赖先建立基线，锁文件定稿后 frozen install；避免依赖降级掺入业务合并。
- **中风险：上游删除本地能力**。插件/分组/兑换码、loading、无限流量、Checkout Session、赞助隐藏列为显式回归项。

部署前记录 frontend 产物 SHA、backend SHA、节点版本、环境变量与代理配置。先测试环境，再小范围切换，观察登录、checkout/status、协议保存与 404/401/5xx。回退恢复上一份**已与当前后端兼容**的前端产物及代理配置；若回退到原始前端需恢复 backend 配对，另评估钱包等已运行数据迁移，不能把代码回退等同于数据库回滚。
