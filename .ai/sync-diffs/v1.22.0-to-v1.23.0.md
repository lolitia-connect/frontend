### 4.1 本轮复核结论（2026-11-17）

后端已注册 `GET /v1/admin/withdrawal/list` 与 `PUT /v1/admin/withdrawal/status`，契约已刷新（298 路由），
`packages/ui/backend-pending.json` 已随之删除（该文件此前仅登记这两条待后端路由；`scripts/backend-contract.mjs`
以 `existsSync(pendingPath) ? … : []` 读取，缺省等价于空数组），`api:check` 与 `api:verify` 均通过且不再提示。
v1.23.0 的五个上游提交均已逐项核对存在：

| 上游 | 核对结果 |
| --- | --- |
| `bee2fe4` 工单已回复 | 存在（`apps/user/src/sections/user/ticket/index.tsx`，状态 2 = Support Replied） |
| `404a5a0` 密码规则 / 后端错误翻译 | 存在（注册、重置、手机端均 8–128；`packages/ui/src/lib/request.ts` 错误码） |

| `4da813b` Nowhere NW3 表单 | 存在（constants/defaults/schemas/useProtocolFields/node-form，`version: 3`、`network: mix`） |

**`id` 线格式（重要）**：后端 `WithdrawalLog.id`/`user_id` 与 `ReviewWithdrawalRequest.id` 均带 `json:",string"`，
即**线上是字符串，纯数字会被拒绝**。核验结论：

- 生成层 `packages/ui/src/services/backend/typings.d.ts` 正确输出 `id: string`、`user_id: string`；
  `backend-openapi.json` 同样是 `{"type":"string"}`，`bun run api:verify` 通过。
- 运行时安全：管理页取自列表响应的 `withdrawal.id`（字符串），原样回传给 `putWithdrawalStatus`，不做数字转换。
- 遗留层 `packages/ui/src/services/admin/typings.d.ts` 仍是 `id: number`，属该**手工维护生成层**的既有不准确
  （该文件为 `// @ts-nocheck`，189 个 `,string` 标记的字段中相当一部分同样标为 `number`），非本轮引入，
  但会误导后续开发。建议后续把 `services/admin` 迁移到生成层或手工校正该批类型。

## 8. 提交前置检查修复（2026-11-17）

`lefthook`/`husky` 的 pre-commit 会对**整仓**运行 `bun x ultracite fix`（Biome），因此提交被
6 条 lint 错误挡住。这 6 条都不是本轮新引入的（4 条在 `HEAD` 就存在，1 条是 fork 自有文件的历史写法），
但既然会阻断提交，就一并修掉，全部为等价改写、无行为变化：

| 文件 | 规则 | 处理 |
| --- | --- | --- |
| `apps/admin/src/sections/servers/index.tsx`（2 条） | `noConstantBinaryExpressions` | 模板字符串恒为真值，原 `${p.name}#${p.id} \|\| \`#${p.id}\` \|\| "—"` 的后两个分支是死代码。改为先算 `instance`（`name#id` / `#id` / `—`），既保留多协议实例的展示意图，又消除恒真表达式 |
| `apps/user/public/oauth/{apple,facebook,github}/index.html`（各 1 条） | `noUselessCatchBinding` | `catch (_e)` → `catch`，与同目录 `google`/`telegram` 已有的写法一致 |
| `scripts/backend-contract.mjs`（1 条） | `noAssignInExpressions` | `(paths[path] \|\|= {})[...] = …` 拆成两行 |

修复后：

```powershell
bun x biome check                 # 739 files, 0 errors
bun x ultracite fix               # exit 0（pre-commit 通过）
bun run api:check / api:verify    # 通过（298 路由 / 479 类型）
bun run test:contract             # 通过（确定性仍成立）
bun run test:proxy                # 8 项通过
bun run test                      # 用户 57 / 管理 65 / UI 3，共 125 项通过
```

注意 `servers/index.tsx` 一处与上游的差异：上游 v1.23.0 直接只显示 `{p.type}`，本 fork 从
`6fea920`（多协议实例）起改为显示 `type-name#id`。本次只修复表达式的恒真问题，**保留 fork 的展示意图**，
不跟随上游退化为仅 `type`。
